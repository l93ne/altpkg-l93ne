# Лабораторная работа № 1. Сборочное окружение и зависимости

Стенд: виртуальная машина x86_64, ALT Workstation 11.1, ветка репозитория p11.
Пакеты и вывод программы идентифицируются учётным именем `l93ne`.

## Классификация зависимостей

| Класс | Пакет | Обоснование | Подтверждение |
|---|---|---|---|
| Инструментальная | `git-core` | нужен разработчику для ведения и публикации работы; в сборке не участвует | есть в хост-системе, отсутствует в окружении: `logs/t7-only-host.txt` |
| Инструментальная | `hasher`, `hasher-priv` | создают изолированное окружение и запускают в нём сборку | `rpm -q` в задании 2; `logs/t7-only-host.txt` |
| Инструментальная | `tree`, `shellcheck`, `rpmdevtools` | просмотр каталогов, контроль сценариев, подготовка дерева сборки | `logs/t7-only-host.txt` |
| Сборочная | `rpm-build` | содержит `rpmbuild`, без него пакет не собрать | входит в базовый набор окружения: `logs/t7-chroot-names.txt` |
| Сборочная | `gcc`, `make`, `glibc-devel` | компилятор, сборщик и заголовки libc; нужны только на этапе сборки | `logs/t7-chroot-names.txt` |
| Сборочная | `libpng-devel` | заголовки, ссылки `libpng*.so` и файлы `.pc` для компоновки | `logs/t3-files-devel.txt`, `logs/t3-qf.txt` |
| Эксплуатационная | `libpng16` | файл разделяемой библиотеки `libpng16.so.16`, загружается при запуске программ | `logs/t3-files-main.txt`; от него зависят 35 установленных пакетов: `logs/t3-whatrequires.txt` |
| Эксплуатационная | `zlib`, `glibc-core` | `libpng16` требует `libz.so.1` и `libc.so.6` при работе | `logs/t3-requires.txt` |
| Эксплуатационная | `sh` (`/bin/sh`) | интерпретатор, которым запускается `hello-l93ne` | `logs/t6-requires.txt` |

Один и тот же проект библиотеки разделён на два пакета. `libpng16` содержит только файлы
`libpng16.so.16*` и документацию. В `libpng-devel` 6 заголовочных файлов (3 файла и 3 ссылки
на них), 2 символические ссылки `libpng.so` и `libpng16.so`, 2 файла `pkgconfig` и сценарий
`libpng16-config`. Запрос `rpm -qf /usr/include/libpng16/png.h` возвращает `libpng-devel`,
и этот же файл есть в `rpm -ql libpng-devel` — проверка замкнута.

Запрос `rpm -q --whatrequires libpng16` по имени пакета находит только `libpng-devel`:
остальные пакеты зависят не от имени, а от файла библиотеки, поэтому обратные зависимости
получены запросом по `libpng16.so.16()(64bit)`.

## Вычисленные зависимости пакета hello-l93ne

В spec-файле нет ни одной директивы `Requires`. Зависимости вычислены при сборке:

| Зависимость | Вид | Откуда взялась |
|---|---|---|
| `/bin/sh` | требуемая | сценарий `find-requires` (обработчик `shebang`) прочитал первую строку `#!/bin/sh` |
| `rpmlib(PayloadIsLzma)` | требуемая | служебная: содержимое пакета сжато LZMA, для установки нужен rpm с поддержкой этого формата |
| `hello-l93ne = 1.0-alt1` | предоставляемая | имя, версия и релиз самого пакета; добавляется всегда |

Команда `echo` — встроенная в оболочку, поэтому зависимости от `coreutils` не появилось.

Этапы в журнале сборки `logs/t6-hello-build.log`: очистка дерева сборки и псевдокорневого
каталога (`rm -rf ... hello-l93ne-buildroot`), установка файла (`install -D -m 755`),
проверки дисциплины сборки (`brp-alt`: Cleaning, Verifying, Checking, Compressing),
вычисление зависимостей (`Finding Provides`, `Finding Requires`), запись пакетов (`Wrote`).

## Воспроизводимость сборки

Пакет `hello-l93ne-1.0-alt1.src.rpm` извлечён из окружения и пересобран одной командой
`hsh ~/hasher <src.rpm>`. Результат появился в `~/hasher/repo/x86_64/RPMS.hasher/`.

Первая попытка завершилась ошибкой `sisyphus_check: check-changelog ERROR`: проверка требует
в журнале изменений адрес сопровождающего в домене дистрибутива. Для локальной сборки проверка
`changelog` добавлена в `no_sisyphus_check` (`env/hasher-config`), журнал неудачной попытки —
`logs/t7-hsh-build-fail.log`.

Имя, версия, релиз, перечни файлов и зависимостей двух сборок совпадают, контрольная сумма
сценария `/usr/bin/hello-l93ne`, извлечённого из обоих пакетов, одинакова. Суммы самих
файлов `.rpm` различаются: в заголовок пакета записываются время и узел сборки.

## Разница состава окружений

В хост-системе 2192 пакета (по именам), в изолированном окружении — 180. Только в хост-системе
находятся 2015 пакетов: графическая среда и прикладные программы (`gnome-shell`, `chromium`)
и инструментальные зависимости разработчика (`git-core`, `hasher`, `rpmdevtools`, `shellcheck`,
`tree`). В окружении остаются базовая система и сборочные средства (`rpm-build`, `gcc`, `make`,
`glibc-devel`). Только в окружении есть три пакета: `sisyphus_check`, `libaudit-common` и пакет
оформления `branding-xalt-kworkstation-release`. Эксплуатационные зависимости собираемого пакета
в окружение попадают лишь тогда, когда они объявлены сборочными.

## Выводы

1. Сборка в hasher не зависит от того, что установлено на машине разработчика: окружение
   создаётся заново из пакетов репозитория, поэтому результат повторяется.
2. Зависимости делятся по этапу, на котором они нужны: инструментальные — разработчику,
   сборочные — при сборке (devel-пакеты, компилятор), эксплуатационные — при работе программы.
3. Эксплуатационные зависимости пакета вычисляются автоматически по содержимому файлов;
   вручную их объявлять не потребовалось.
4. Сборка и установка в окружении выполняются без прав суперпользователя: пакет собирает
   пользователь `builder`, а установку имитирует служебный `root` (rooter).
